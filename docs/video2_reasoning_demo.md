# Scene-Graph Reasoning Demo

This demo is a compact semantic-reasoning showcase intended for recording and report evidence. It uses one animated Actor and the existing project reasoning interfaces. Robot navigation is intentionally not started.

## Launch

From the repository root:

```bash
./scripts/start_video2_reasoning_demo.sh
```

Stop with:

```bash
./scripts/stop_video2_reasoning_demo.sh
```

Gazebo and RViz start automatically and remain open until the stop helper is called.

## Request

The demo injects the structured semantic request corresponding to:

```text
I want to see classical art.
```

This demo does not test speech recognition or natural-language parsing. It starts from the existing structured request interface so that the recording focuses on the scene graph and semantic decision.

## Existing Graph Facts

The reasoner uses the project semantic graph. The relevant facts are:

```text
roman_statue : style = classical
roman_statue -> located_in -> ancient_art_hall
```

The existing semantic route mapping then resolves:

```text
ancient_art_hall -> south_west_gallery
```

The prepared navigation target is:

```text
x = -10.0
y = -21.5
yaw = 1.5708
```

These coordinates come from the existing route configuration; they are not generated by an LLM.

## Runtime Flow

```text
StructuredRequest
      |
      v
Semantic graph
      |
      v
Deterministic reasoner
      |
      v
roman_statue
      |
      v
ancient_art_hall
      |
      v
south_west_gallery
      |
      v
prepared navigate_to action
```

The monitor reads actual ROS messages for the request, session/reasoning state, graph facts, selected semantic entities, and prepared action.

## Why Navigation Is Not Started

This demonstration is deliberately separated from the social-navigation video. Its purpose is to make the semantic inference easy to see and verify without requiring a second long navigation run.

The project already demonstrates physical robot navigation separately in the final eight-Actor social-navigation scene and in the navigation acceptance tests.

## Expected Monitor Evidence

The compact monitor should show information equivalent to:

```text
Request:       classical art
Artwork:       roman_statue
Style:         classical
Room:          ancient_art_hall
Route:         south_west_gallery
Skill:         navigate_to
Goal:          (-10.0, -21.5, 1.5708)
Navigation:    prepared, not dispatched
```

The exact formatting may differ, but displayed values are derived from the running ROS components and route configuration.

## Reproducibility

The full demo is started with a single command:

```bash
./scripts/start_video2_reasoning_demo.sh
```

No manual ROS topic publication is required during the recorded run.
